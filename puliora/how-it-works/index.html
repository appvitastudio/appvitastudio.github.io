How Puliora works

A deterministic engine: the same text and options always give the same result, and every change can be explained, skipped and reversed.

  • Runs locally
  • Nothing uploaded
  • No account
  • Free

Presets and modes

  • Safe (default) removes only characters that have no function in their context.
  • Strict also normalises typographic no-break spaces, full-width and styled letters, ligatures, redundant emoji selectors and look-alike letters in mixed-script words.
  • Minimal removes only truly invisible characters and leaves spaces and visible characters alone.
  • Advanced lets you set Remove / Replace / Keep for every rule and add your own rules; Developer adds code points, bytes and escapes; Document repair fixes layout.

Typography (dashes, quotes, ellipsis) and layout repairs are never applied by a preset: you enable them explicitly.

What is preserved, and how

Each character is judged with its neighbours: a zero-width joiner is kept between two emoji or next to a letter of a script that uses joiners (Arabic, Persian, Indic scripts and others); a variation selector is kept only right after a base that defines that sequence (from emoji-variation-sequences.txt and StandardizedVariants.txt); direction marks (LRM, RLM, ALM) are kept when the same line contains a right-to-left letter (in source code only when one is within a few characters), and only one per position; bidi embeddings and isolates are kept only on lines that contain right-to-left letters, never in source code (overrides on such lines are kept in Safe mode for your review); tag characters are kept only in subdivision flag sequences; no-break spaces are kept between digits and before French punctuation.

Unicode data

The engine does not rely on the browser's own Unicode tables, which differ between versions. It ships tables generated from the official Unicode Character Database, version 18.0.0: UnicodeData.txt, NameAliases.txt, Scripts.txt, DerivedCoreProperties.txt, PropList.txt, StandardizedVariants.txt, emoji-data.txt, emoji-variation-sequences.txt, and confusables.txt from UTS #39. Privacy you can verify

The pages declare connect-src 'none' in their Content Security Policy, so page scripts cannot open network connections. A meta-tag policy does not cover web workers, so the background worker that cleans long texts and files disables fetch, XMLHttpRequest, WebSocket, EventSource and importScripts as soon as it starts. Open your browser's developer tools, go to the Network tab and paste text: no request appears. Nothing is stored unless you enable the local history (counts only) or save custom rules.

Exact, reversible changes

Every pass (characters, custom rules, layout, normalisation) produces edits on the original text, composed into one list of non-overlapping changes. That list drives the Changes view, lets you skip individual changes, and — exported in the JSON report — reconstructs the original text exactly.

Tests

The engine has an automated test suite covering every rule category, emoji sequences, Persian, Arabic, Hebrew, Indic scripts, CJK, Vietnamese, combining characters, JSON/CSV/XML/DOCX structure, large texts, security of reports and randomised round-trip tests that check that the original can always be rebuilt from the output.

Limits

  • Statistical AI watermarks are patterns in word choice, not characters: Puliora cannot remove them, and nothing short of rewriting can.
  • Puliora does not detect AI-written text and cannot tell who wrote a text.
  • Not finding invisible characters does not prove the absence of other metadata or provenance signals (for example in the original file).
  • Look-alike detection relies on mixed-script words; a word written entirely in another script is reported but never changed automatically.
  • De-hyphenation cannot know every compound word: review those changes.
  • PDF files are not parsed; rich text formatting is lost when you paste into a plain text box.
  • The text cleaner accepts up to 20 MB of text at a time; Files & batch accepts up to 25 MB per file.
